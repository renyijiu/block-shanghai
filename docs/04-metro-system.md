# 04 · 地铁系统设计

地铁是本项目和参考项目最大的区别，也是“方块上海”最有辨识度的玩法。

## 1. 目标与原则

- **真实线网**：线路、站点、颜色、出入口、地下/高架结构全部来自真实数据。
- **看得见**：高架段在城市里有桥、有列车开过，站在街上就能看到。
- **坐得上**：进站、刷卡、候车、上车、报站、换乘、选出口出站，一套完整流程。
- **可收集**：集站、集线路，有专门的任务和成就。
- **分层交付**：分四层做，每层单独可玩、可上线。
- **列车状态只由时间决定**：列车位置是“游戏时间 → 位置”的纯函数，不做逐帧物理模拟，方便测试，也不用存档。

## 2. 与参考项目对比

| | 方块羊城 | 方块上海 |
| --- | --- | --- |
| 站点 | 18 个，手填坐标 | 全网，从 OSM 烘焙 |
| 线路 | 只有站点上的线路标签 | 完整线路、走向、颜色、支线和大站车 |
| 乘车 | 菜单选站 → 黑屏传送 | 第 1 层保留快速到达；第 3 层完整乘车 |
| 地面表现 | 地铁口模型 | 地铁口 + 风亭 + 高架桥 + 高架车站 + 运行的列车 |
| 站内 | 无 | 站厅、站台、车厢、换乘通道 |
| 收集 | 乘坐次数 | 集站图鉴、线路徽章、成就 |
| 生成方式 | 开局一次性建全部 18 个口 | 跟随城市分块流式加载 |

**对游戏的意义**：

- **3、4 号线**共用一段高架，位于内环西侧和北侧，就在核心区里，是第 2 层优先做的线路。
- 5、16、17 号线和磁浮以高架为主，都在外圈，适合做“高架看风景”的乘车体验。
- 12–15、18 号线全在地下，地面只有出入口。

### 3.2 烘焙步骤（`tools/bake-metro.mjs`）

1. **拉取**：从 Geofabrik 上海提取包里用 `osmium tags-filter` 切出下列要素，导出为 OSM XML（保留 relation 成员顺序，GeoJSON 会丢掉顺序）
   - subway / light_rail / monorail 的 route relation
   - 成员轨道 way 及其节点坐标
   - stop / platform 节点和 `public_transport=stop_area` relation
   - `railway=subway_entrance` 节点（`ref` 为出口编号，如果有）
2. **线路**：按 `ref` 归并上下行和支线 relation；从 `colour` 取颜色；`name` / `name:en` 取中英文名。
3. **站点**：按 relation 成员顺序得到停站序列；用 `stop_area` 把同一车站不同线路的站台合并成一个换乘站。没有 stop_area 的，按“同名 + 300 米内”合并。
4. **轨道**：把成员 way 按顺序拼成连续折线。每段按标签标记结构：
   - `tunnel=yes` 或 `layer < 0` → `tunnel`
   - `bridge=yes` 或 `layer > 0` → `viaduct`
   - 其余 → `ground`
5. **共线**：同一条 OSM way 被多条线路引用时（3 / 4 号线），标记为共线段，只生成一套桥梁。
6. **里程**：在**投影前**按真实经纬度算每段的真实公里数（`realKm`），用于票价和运行时间；投影后的格坐标只用于显示。
7. **出入口**：把每个出入口挂到最近的车站（同一 stop_area 优先）。
8. **人工修正**：读取 `tools/metro.overrides.json`，修正颜色、站名、缺失车站、新开通区段等。
9. **输出**：`src/cities/shanghai/data/metro.json`，打印每条线的站数、长度、各结构占比，方便和官方数据对照。

## 4. metro.json 数据模型

```jsonc
{
  "version": 1,
  "generatedAt": "2026-10-30",
  "lines": [
    {
      "id": "L2",
      "ref": "2",
      "name": "2号线",
      "nameEn": "Line 2",
      "color": "#97D700",
      "kind": "subway",                // subway | apm | maglev
      "loop": false,
      "services": [                    // 运营交路：上下行、支线、大站车
        {
          "id": "L2-east",
          "terminus": "s_pudong_airport",
          "stops": ["s_east_xujing", "...", "s_pudong_airport"],
          "express": false
        }
      ],
      "track": [                       // 轨道折线，按结构分段
        {
          "structure": "tunnel",       // tunnel | viaduct | ground
          "pts": [[x, z], ...],
          "realKm": 3.42,
          "shared": [],                // 共线的其他线路 id
          "chunks": ["1,0", "2,0"]
        }
      ]
    }
  ],
  "stations": [
    {
      "id": "s_peoples_square",
      "name": "人民广场",
      "nameEn": "People's Square",
      "pos": [x, z],
      "lines": ["L1", "L2", "L8"],
      "platforms": [
        { "line": "L2", "structure": "tunnel", "type": "island", "chainage": { "L2-east": 5.81 } }
      ],
      "exits": [ { "ref": "1", "pos": [x, z] } ],
      "transferMin": 5                 // 换乘步行时间（真实分钟），默认 4
    }
  ],
  "rules": {
    "fare": { "baseKm": 6, "baseYuan": 3, "stepKm": 10, "stepYuan": 1 },
    "avgSpeedKmh": { "subway": 35, "apm": 25, "maglev": 220 },
    "dwellSec": 40
  }
}
```

`chainage` 是车站在该交路上的真实里程（km），时刻表和运行时间都按它算。

## 5. 第 1 层：线网与路线规划

替换参考项目的传送菜单。

### 路网图

- 节点：每个（车站, 线路）一个“站台节点”，每个车站一个“站厅节点”。
- 边：
  - **乘车边**：同一交路相邻两站，权重 = 区间里程 ÷ 平均速度 + 停站时间
  - **换乘边**：同一车站不同线路的站台之间，权重 = `transferMin`
  - **进出站边**：站厅 ↔ 站台，权重 0
- 算法：Dijkstra，几百个节点，瞬间出结果。
- 两种模式：**最快**、**少换乘**（每次换乘额外加 10 分钟）。

### 票价

按上海地铁的里程计价规则：6 km 内 3 元，之后每 10 km 加 1 元，按最短路径的真实里程计算。磁浮单独计价。具体规则 P2 开发前对照官网核对，写进 `rules.fare`。

### 时间

- 运行时间按真实分钟算出来，再折算成游戏时间推进天空时钟。
- 第 1 层的“快速到达”：淡出 → 按路线时间推进时钟、扣票价 → 在目的站出口淡入。

### UI

- **线路图面板**：按 metro.json 的真实走向画彩色线路图，可缩放拖动；点车站看所在线路、出口和附近景点。
- **路线规划**：起点默认是当前车站，终点可搜索（中文 / 拼音）或在图上点选；结果显示“2 号线 → 世纪大道换 4 号线 · 约 18 分钟 · 4 元”。
- 按钮：**快速到达**（第 1 层）/ **进站乘车**（第 3 层上线后）。

### 测试

路线规划、票价、里程都是纯函数，用一份小型测试线网写单元测试（含环线、支线、共线）。

## 6. 第 2 层：地面上看得见的地铁

### 高架桥

- 对 `structure = viaduct` 的轨道段，按分块生成：桥面梁（双线宽约 8 格）+ 桥墩（每 12 格一个，用 InstancedMesh）。
- 桥面高度 9 格；遇到道路、河流时保持高度。
- 结构从高架变成隧道处生成**坡道 + 隧道口**（坡长约 40 格）。
- 共线段（3 / 4 号线）只生成一套桥，桥侧色带用两条线的颜色。

### 高架车站

- 横跨在道路或轨道上方的长方体站房：站台层 + 雨棚 + 线路色带 + 中英文站名牌。
- 地面有楼梯 / 扶梯入口，作为进站交互点。

### 地下车站在地面上的表现

- **出入口**：放在 OSM 出入口的位置，带红色“M”标识和站名、出口编号。
- **风亭**：车站附近随机放 1–2 个。

### 列车

- **时刻表函数**：每个交路按发车间隔 `headway` 发车（高峰 3 分钟、平峰 6 分钟，可配置）。给定游戏时间 t，算出每列车在交路上的里程 s(t)：区间内匀加速 → 匀速 → 匀减速，到站停 `dwellSec`。
- 环线（4 号线）按环形里程取模。
- **只渲染看得见的车**：s(t) 落在视野内的高架或地面段时，才从对象池里取一个列车模型摆上去，最多 12 列。
- **模型**：3 节编组，白色 / 银色车身 + 线路色带，车头 LED 显示“往 XX”，夜间车窗亮灯。

## 7. 第 3 层：站内与乘车

### 场景方案

站内和车厢是**独立的 THREE.Scene**，进出站时淡入淡出切换，不在城市地形里挖洞（原因见 [02](./02-architecture.md#场景切换)）。

### 场景模板

按“结构 × 站台类型”做 4 个参数化模板，用数据填站名、线路色、出口列表：

| | 岛式站台 | 侧式站台 |
| --- | --- | --- |
| 地下 | 全高屏蔽门 | 全高屏蔽门 |
| 高架 | 半高屏蔽门，站台外能看到天空和城市轮廓 | 同左 |

站台类型由 OSM 站台数推断（一个站台 → 岛式，两个 → 侧式），推断不了就默认岛式。

- **站厅**：售票机、闸机、出口指示牌（出口编号 + 方向）、线路色导向条、中英文站名。
- **站台**：屏蔽门、列车到站倒计时屏（读时刻表）、门楣上的线路图。
- **车厢**：纵向座椅、扶杆、拉环、门上方的线路进度屏（高亮下一站）。窗外：
  - 地下段：黑色隧道 + 掠过的灯带
  - 高架段：MVP 用天空盒 + 城市剪影；后续可以考虑在城市场景里让镜头跟着列车走（实景乘车）
- **换乘通道**：一段走廊，地面有线路色导向。

### 流程

```
街道 ──进入出入口──► 站厅 ──过闸（单程票或交通卡）──► 站台
                                                       │ 等车（倒计时，可跳过）
                                                       ▼
                     ┌───────────────── 车厢（逐站行驶，到站开门约 3 秒，可下车）
                     ▼
               站台（目的站）──换乘──► 换乘通道 ──► 站台（另一条线）
                     │
                     ▼
               站厅 ──选择出口──► 街道（OSM 对应出入口的位置）
```

### 报站

根据数据自动生成中英文报站：

> 下一站：人民广场。可换乘 2 号线、8 号线。
> Next stop: People's Square. You can transfer to Line 2 and Line 8.

MVP 只做文字气泡，语音以后再考虑。

### 时间压缩

- 每个区间的展示时长 10–15 秒，可以“跳到下一站”或“直达目的地”。
- 天空时钟按**真实运行分钟**推进，跟展示时长无关。乘一趟车出来，天色会相应变化。

### 车厢里的人

NPC 数量随时段和线路变化：早高峰 7:00–9:30、晚高峰 17:00–19:30 时，1、2、9 号线等干线车厢满员、没座位；平峰有座；深夜车厢空。

## 8. 第 4 层：收集与任务

### 新增事件

| 事件 | 参数 |
| --- | --- |
| `metroEnter` | 车站 |
| `metroExit` | 车站、出口编号 |
| `metroRide` | 线路、上车站、下车站、经过的区间 |
| `metroTransfer` | 车站、原线路、新线路 |

### 收集

- **集站图鉴**：在某站进站、出站或换乘即算“到访”，只坐车经过不算。图鉴按线路分页，显示站名、所在区、到访时间。
- **线路徽章**：坐过一条线的所有区间，就点亮这条线的徽章。

### 成就和任务（示例）

| 名称 | 条件 |
| --- | --- |
| 第一次坐地铁 | 完成一次乘车，获得纪念交通卡 |
| 环线一周 | 4 号线不出站坐满一圈 |
| 四线换乘 | 在世纪大道站换乘一次 |
| 换乘达人 | 在 5 个不同车站换乘过 |
| 早高峰体验 | 7:30–9:00 乘坐 1 号线或 2 号线 |
| 磁浮初体验 | 乘坐磁浮，获得磁浮车票 |
| 黄浦江底下 | 乘 2 号线从南京东路到陆家嘴 |
| 从头坐到尾 | 到访任一线路的两个终点站 |
| 集站 50 / 100 / 全网 | 到访车站数达标 |

每日任务池增加：乘坐 2 条不同线路、到访 1 个新车站、从指定出口出站去某个景点。

### 末班车（可选难度）

运营时间之外（约 23:00 到次日 5:30，各线不同），出入口卷帘门关闭，只能步行或打车。默认关闭，在设置里开启。

## 9. 尺度与表现约定

| 对象 | 尺寸（格，1 格≈1 米） |
| --- | --- |
| 车厢 | 长 14 × 宽 3 × 高 3.6 |
| 列车（3 节编组） | 约 45 长 |
| 站台 | 长 50 |
| 高架桥面 | 离地 9，宽约 8（双线） |
| 桥墩间距 | 12 |
| 隧道口坡道 | 长 40 |
| 地面出入口 | 约 6 × 4 |

真实列车长 140 米左右，而市区站间距压缩后只有 200–300 格，所以必须用缩短的编组。

## 10. 流式加载与性能

- 高架桥、桥墩、高架站、出入口、风亭都按分块生成，交互点用分块的 owner 登记，卸载时一起清理。
- 每个分块的桥面合并成一个网格；桥墩、出入口用 InstancedMesh。
- 线网图、时刻表、路线规划是全局数据（几百个站），常驻内存。
- metro.json 抽稀后预计几百 KB；高架桥需要它，所以开局加载。
- 列车模型对象池，同屏最多 12 列。

## 11. 验收标准

| 层 | 验收 |
| --- | --- |
| 第 1 层 | 线路图面板显示全部线路，颜色正确；任选两站，路线规划和官方 App 结果一致或合理；票价符合规则；快速到达后天空时钟推进正确 |
| 第 2 层 | 在中山公园、上海火车站附近能看到 3/4 号线高架和运行的列车；高架和隧道交界处有坡道；中档画质帧率 ≥ 50 |
| 第 3 层 | 能从任一出入口进站，完成候车、乘车、换乘，并从选定出口出站；报站内容正确；可以跳过 |
| 第 4 层 | 集站图鉴、线路徽章、上述成就都能正确触发并存档 |

## 12. 风险与待定

| 项 | 说明 | 应对 |
| --- | --- | --- |
| OSM 滞后 | 新开通线路或区段可能没录入 | 发布前对照官网线网核对；用 `metro.overrides.json` 补 |
| 支线和大站车 | 5、10、11 号线有支线，16 号线有大站车 | 数据模型用 services 表达；第 1 层先只做普通交路 |
| 站台数据不全 | 站台类型、开门方向缺失 | 推断不了就用默认值，不影响主流程 |
| 英文站名 | 部分站点缺少 `name:en` | 用 overrides 补；缺失时临时显示拼音 |
| 实景乘车 | 高架段让镜头跟着列车在城市场景里走，视觉效果最好，但要同时加载沿线分块 | 第 3 层之后单独评估 |
| 标识 | 不照搬官方 logo 和视觉规范 | 用通用的红色“M”和线路色 |
