# 01 · 参考项目分析：方块羊城（Block Guangzhou）

> 分析日期：2026-10-30
> 参考仓库：<https://github.com/ns2250225/guangzhou>（分析时为提交 `2b74c37`）

本文记录参考项目怎么做的、哪些思路可以借鉴、哪些地方不照搬。只借鉴设计思路，**不复制代码**，原因见文末“许可”一节。

---

## 1. 项目概况

| 项 | 内容 |
| --- | --- |
| 定位 | Minecraft 方块风格 + 城市漫游 + 拍照收集图鉴的广州观光模拟器 |
| 技术栈 | Vue 3 + Three.js（WebGL）+ Vite，纯前端，无服务器 |
| 规模 | 约 9000 行源码 + 967 行 PRD；只有 1 次提交 |
| 存储 | localStorage 存档，IndexedDB 存照片 |
| 资源 | 没有外部模型和贴图，所有建筑都是代码拼出的方块，招牌文字用 canvas 渲染 |

## 2. 模块拆解

| 模块 | 文件 | 做法 | 本项目的处理 |
| --- | --- | --- | --- |
| 坐标投影 | `geo.js` | 以城市中心为原点做局部投影；半径 12km 内 1km = 200 格，圈外距离 × 0.35 | ✅ 采用同样思路，自行实现（`src/engine/geo/projection.ts`） |
| 地理数据 | `geo.js` | 珠江、道路、山丘、公园、区划都是**手敲的经纬度折线和点**；区划用种子点做 Voronoi | ❌ 改为从 OSM 自动烘焙 |
| 水面与道路 | `world.js` | 河流 = 折线 + 宽度，生成条带网格；水面用 Reflector 做实时倒影；水面上的路段自动变成桥 | ✅ 思路可用；长江口、湖面改用多边形 |
| 城市建筑 | `city.js` | 240 格一块流式生成；每块分成 24 格地块，按区域“画像”（cbd/office/resi/old/village）随机盖楼；近处加细节，远处简化 | ✅ 框架照搬，换成上海的建筑画像 |
| 景点 | `landmarks/*.js` | 44 个景点各写一个建模函数，用 `box / prism / beam / gableRoof / sign` 拼方块；带 LOD、按距离加载卸载、可贴到岸边 | ✅ 框架照搬，模型全部重做 |
| 建模工具 | `builder.js` | 方块几何按材质合并成少量网格；同时登记碰撞盒 | ✅ 同类工具自行实现 |
| 交通 | `transport.js` | 巴士沿道路折线往返、游船沿河道、电梯和索道是脚本动画、车流随机生成在玩家附近 | ✅ 巴士、船、电梯复用思路；**地铁重做** |
| 地铁 | `geo.js` + `Panels.vue` | 18 个站点坐标 + 地面入口模型 + 一个“选目的地 → 黑屏 → 传送”菜单。没有线路、轨道、列车、站内 | 🔁 本项目的重点，见 [04-metro-system.md](./04-metro-system.md) |
| 交互 | `transport.js` `InteractRegistry` | 交互点注册表，按 owner 批量增删；E 键触发 | ✅ 采用，改为跟随分块流式注册 |
| 摄影 | `photo.js` | 第一人称 / 第三人称 / 自拍，6 种滤镜；按视锥 + 遮挡识别画面里的景点，自动解锁图鉴 | ✅ 采用 |
| NPC | `npc.js` | 6 类路人会走路、聊天、拍照、等车；对白是粤语 | ✅ 采用，对白换沪语 |
| 天气昼夜 | `sky.js` | 晴 / 阴 / 雨 / 台风随机切换，昼夜循环，夜间窗灯和霓虹 | ✅ 采用，加梅雨和雪 |
| 任务与收集 | `data.js` `store.js` | 新手任务、区域任务、每日任务全部由数据驱动，事件计数自动结算 | ✅ 采用 |
| UI | `Menu.vue` `GameView.vue` `Panels.vue` | MC 风格 UI，移动端摇杆、横竖屏提示、全屏 | ✅ 参考交互，重新实现 |

## 3. 广州内容写死在哪里

城市内容没有抽象出来，分散在很多文件里：

| 位置 | 写死的内容 |
| --- | --- |
| `geo.js` | 原点、河流、道路、区划种子、山丘、公园、巴士线路、地铁站、码头（360 行） |
| `data.js` | 美食、文化、纪念品、商店、任务、粤语对白（143 行） |
| `landmarks/` | 44 个景点建模（约 2400 行） |
| `Game.js` | 出生点列表、广州塔电梯、白云索道、夜游文案 |
| `city.js` | 珠江新城 / 天河北 / 琶洲的建筑画像，木棉、榕树行道树 |
| `photo.js` | “岭南复古”等滤镜名 |
| `Menu.vue` `Panels.vue` | “广州地铁”“羊城”等文案，地铁线路配色 |

合计约 2900 行是纯广州内容，其余引擎代码里也掺着城市引用。原作者 TODO 里写了“可扩展到上海等城市的地图框架”，但没做。本项目从第一天就把引擎和城市分开，见 [02-architecture.md](./02-architecture.md)。

## 4. 值得借鉴的设计

1. **核心区 1:1 + 外圈压缩的投影**：市中心保持真实距离感，远郊景点也能走到。
2. **分块流式生成 + 画像驱动的程序化建筑**：不用为整座城建模，只给少数景点精细建模。
3. **景点三级（S/A/B）**：S 级高度还原，A 级主要建筑，B 级只做氛围；控制工作量。
4. **拍照即收集**：拍照时自动识别画面里的景点并解锁图鉴，玩法循环简单有效。
5. **任务数据驱动**：任务条件用 `{ type, ... }` 描述，靠事件计数结算，加内容不用改逻辑。
6. **owner 机制**：碰撞、交互点、人群都按 owner（分块 / 景点）登记，卸载时一次清理。
7. **三档画质**：按画质调整视距、细节半径、NPC 数量、倒影和阴影。

## 5. 不照搬的地方

| 问题 | 原做法 | 本项目 |
| --- | --- | --- |
| 地理精度低、维护难 | 手敲经纬度折线 | OSM 烘焙脚本自动生成（[03](./03-coordinates-and-data.md)） |
| 坐标系不明确 | 没说明用的是 WGS-84 还是 GCJ-02 | 统一用 WGS-84，写进约定 |
| 城市写死在引擎里 | 散落在十几个文件 | 城市包契约（[02](./02-architecture.md)） |
| 交互点一次性全部注册 | 开局把 18 个地铁口全部建好 | 跟随分块流式注册；上海有几百个站，必须这样做 |
| 地铁只是传送 | 菜单 + 黑屏 | 真实线网、高架列车、站内场景、乘车（[04](./04-metro-system.md)） |
| 尺度没有文档 | 地图 1 格≈5m，人物 1 格≈1m，建筑高度另一套，只能从代码推出来 | 写成明确约定（[03](./03-coordinates-and-data.md)） |
| 没有测试 | — | 纯函数模块（投影、路线规划、票价）写单元测试 |
